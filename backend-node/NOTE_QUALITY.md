# 后台学习笔记内容标准

后台模型继续只补全 Codex 已识别的学习目标。新增词义、搭配和相关表达是该笔记的教学材料，不会成为额外学习记录、遇见次数或复习证据。

单词笔记先讲本次语境中的含义和词性，再区分这个词其他常见、实用的含义。解释应包含主要句型、常见搭配/相关短语的意思与使用场景，以及有用的易混点；单一常见义的词讲清可数性、量词或日常组合即可，不为了凑栏目添加冷僻或不确定的词义。短语、语法和纠错仍围绕原目标展开。

例如，`secure funding` 应先解释动词“争取到资金”，再在同一笔记中区分 secure 的其他动词用法和形容词用法。`secure a job` 与 `a secure job`、`secure something with a strap`、`feel secure` 等模式需要说明含义，不能只堆中文译词。相关表达不表示用户对它们存在新的学习困难。

`meaning` 保持可作卡片摘要的简短释义；细节放在已有的 `explanation`，用短分段或列表组织。解释使用已确认的解释语言，原例句使用目标语言，翻译使用解释语言。需要覆盖多个用法时给 4～5 个不同的自然例句，简单目标至少两个。生成内容使用现有字段，不增加数据库迁移。

结构化文本字段现有上限为 2,000 个 Unicode 字符，因此提示词将 explanation 目标设为不超过 1,800 字符，完整例句另存 examples，避免重复挤占解释空间。各适配器的输出预算从 1,600 提高到 3,600 token，给较详细的 JSON 留足空间。生成仍在后台，前台捕获不等待它。

已有笔记不会因这次提示词修改而批量重写。工作器仍保留已有同义 explanation、手动/空白自定义笔记及用户编辑；内容版本、账号隔离、幂等、删除和遇见/复习规则不变。较丰富内容适用于新的空白待补全笔记；旧笔记需要用户明确请求重写。

验证：`node --test --test-concurrency=1 test/providers.test.js test/enrichment.test.js test/enrichment-dedup.test.js` 在专用临时 PostgreSQL 17.10、Node 24.19.0 下通过 50 项，零失败/跳过。测试覆盖三种适配器的完整内容传输、一个丰富 secure 笔记的持久化、相关短语不增加点或遇见，以及旧手动解释不被替换。临时数据库容器已清理。

这些确定性测试不能证明真实模型的解释质量。上线前可直接调用已配置 provider，对 `secure`（无语境）、`secure funding`、`celery`、`hold a grudge` 及一道纠错做人工内容评审，不调用保存接口：检查语境义优先、词性清楚、搭配真实、例句自然、语言偏好正确、JSON 字段长度合规，以及没有照抄提示词示例。保留实际输出、用时和验证结果；不将样本写入用户的真实学习库。
